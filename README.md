# Spectrier (CPS-Debugger)

The target system is a Bosch Rexroth `ctrlX` inverted-pendulum cart.
The controller is written in C, compiled to WebAssembly, and
instrumented to emit a per-tick control-flow trace alongside
synchronised 1 kHz sensor readings.

The research question: given only the sensor stream, can a model
reconstruct what the controller did internally (function calls and
branches) at fine grain?

The codebase contains (1) sensor encoders that map raw 7-channel
sensor windows to dense representations (Chronos-2, MOMENT-1, plus a
from-scratch ViT-Small JEPA encoder), (2) trace generators that map
those representations to token sequences (AR, AR-modern, MDLM), and
(3) the evaluation protocol that scores generated traces against
ground truth on a deterministic `100K` subset of the held-out test
sessions (defined in `Evaluation protocol` below).

## Data

Sensor channels (7), sampled at 1 kHz:

| Channel | Description |
|---|---|
| `pendulum_state` | FSM state: 0 SWINGUP, 1 BALANCE, 2 RESET |
| `iteration` | Episode counter, 0 to 23, monotonic |
| `target_x` | Cart target position (m) |
| `current_x` | Cart actual position (m) |
| `velocity` | Cart linear velocity (m/s) |
| `current_angle` | Pendulum angle (rad) |
| `angular_velocity` | Pendulum angular velocity (rad/s) |

Each tick emits a trace of median length 91 tokens (range 3 to 108),
drawn from a 648-symbol vocabulary. A token is a triple
`(wasm_function_id, source_pc, target_pc)` identifying a single
control-flow edge in the WASM bytecode: while executing
`wasm_function_id`, control flowed from `source_pc` to `target_pc`.
`source_pc` and `target_pc` are byte-offsets of WASM instructions
inside the function. Within a function the trace records branches
(if/else, loop, switch). When the controller calls another function,
subsequent tokens carry that function's id until it returns. Library
calls (`cos`, `sin`, `log`, `__rem_pio2_large`, etc.) look the same
as any other call.

Sessions are named by capture timestamp,
e.g. `2025-03-17_10-36-44.parquet`. Per-tick rows carry the sensor
readings, the trace tokens, the FSM state, and the tick timestamp.

### Trace example

A BALANCE-tick (`pendulum_state=1`) trace of length 94, first 12
tokens decoded against `pruned_token_mapping.json` and the
`functions_kept` map:

```
pos  tid    function            src_pc -> tgt_pc
  0   10    21:execute             101 ->  113
  1   19    21:execute             155 ->  201
  2   21    21:execute             251 ->  297
  3   22    21:execute             348 ->  350
  4   75    22:tick                209 ->  253
  5  152    26:ethercat_read       156 ->  247
  6  155    26:ethercat_read       372 ->  490
  7  158    26:ethercat_read       636 ->  755
  8  161    26:ethercat_read      1022 -> 1153
  9  166    27:waxi_end_access     101 ->  169   <- call deeper
 10  163    26:ethercat_read      1381 -> 1383   <- back in caller
 11   77    22:tick                336 ->  418
```

`pos` is the index in the trace token sequence; the 12 rows above
are tokens 0 through 11 of the 94-token trace. Tokens 4 and 11 are
in `tick`; tokens 5-8 are inside `ethercat_read`, which `tick`
called; token 9 is inside `waxi_end_access`, which `ethercat_read`
called; token 10 is back in `ethercat_read`.

Full vocabulary inventory:
[outputs/fm_trace_eda/architecture_eda/](outputs/fm_trace_eda/architecture_eda/).
The WASM PC-to-block lookup table that maps `source_pc` and
`target_pc` to source-code locations is at
`<capture>/code/layout.json` in the raw datalogs.

## Pipeline

The pipeline has two stages that are trained separately.

```
raw sensor window (B, 7, 500)         # 7 channels, 500 ticks = 500 ms at 1 kHz
        |
        v
 +-----------------+        sensor encoder is pretrained with
 | Sensor encoder  |        self-supervised learning (from-scratch
 |   (frozen at    |        ViT-Small JEPA: data2vec / V-JEPA-style EMA
 |   trace-gen     |        latent prediction; Chronos-2 and MOMENT-1:
 |   time)         |        third-party pretrained checkpoints)
 +-----------------+
        |
        v
 sensor embedding (B, K, d_emb) or (B, d_emb)
        |
        v
 +-----------------+        trace generator is trained supervised on
 | Trace generator |        (sensor_emb, ground-truth trace) pairs.
 |   (autoregressive        Encoder weights stay frozen here.
 |    or diffusion) |
 +-----------------+
        |
        v
 trace tokens (B, L)
```

### Stage 1: sensor encoders

Self-supervised representation learners over the 7-channel sensor
window. Pretrained once, then frozen.

| Encoder | Pretraining | Params | Output |
|---|---|---|---|
| Chronos-2 | Foundation model, vendor checkpoint | (vendor) | (B, 512) |
| MOMENT-1 | Foundation model, vendor checkpoint | (vendor) | (B, 512) |
| V-JEPA-2 (video) | Self-supervised on video, vendor checkpoint | (vendor) | (B, d_v) |
| CoTracker3 (video) | Self-supervised point tracking, vendor checkpoint | (vendor) | (B, d_v) |
| ViT-Small JEPA (this codebase) | JEPA / data2vec EMA latent prediction on the 7-channel windows, trained from scratch on the train sessions | ~41 M | (B, 4, 256) |

The from-scratch JEPA encoder uses a ViT-Small backbone with a conv
frontend (500 ticks to 25 patches), 12 axial-attention layers
(alternating time and channel), and a Perceiver pool with K=4 learned
queries.

### Stage 2: trace generators

Autoregressive or diffusion decoders over the 648-token vocabulary,
conditioned on the (frozen) sensor embedding from stage 1.

| Generator | Architecture |
|---|---|
| MDLM | Discrete diffusion. Reports `exp(ELBO)`, not directly comparable to AR perplexity. |
| AR | Pre-norm transformer, GELU + LayerNorm, AdamW. Earlier baseline. |
| AR-modern | RMSNorm, SwiGLU, QK-Norm, Muon optimizer for 2D weights. Conditioning is a prefix token by default; for dense sensor outputs (K=4 tokens), Flamingo-style gated cross-attention is an optional drop-in. |

### Evaluated combinations

Rows in
[outputs/fm_candidates/results/cps_fm_candidates.xlsx](outputs/fm_candidates/results/cps_fm_candidates.xlsx)
on the `Stratified 100K` sheet.

| Sensor encoder | Trace generator | Note |
|---|---|---|
| Chronos-2 | MDLM | Discrete diffusion baseline |
| Chronos-2 | AR-modern (prefix) | Strongest baseline |
| Chronos-2 + V-JEPA-2 video | AR-modern (prefix) | Video conditioning |
| Chronos-2 + CoTracker3 video | AR-modern (prefix) | |
| MOMENT-1 | AR-modern (prefix) | Alternative sensor encoder |
| ViT-Small JEPA (frozen) | AR-modern (prefix) | Primary from-scratch-encoder variant |
| ViT-Small JEPA (frozen) | AR-modern (Flamingo cross-attn over K=4 tokens) | Cross-attention conditioning ablation |
| ViT-Small JEPA (frozen) **+ derived sensor features** | AR-modern (prefix) | Adds 16 derived features (PLC threshold crossings, `cos(theta)`, `sin(theta)`, log-saturation terms, 5-tick lags) concatenated to each of the K=4 encoder tokens. Best per-state and aggregate of the JEPA variants. |

### Per-state NED (5-fold median), AR-modern decoder held fixed

| State | Chronos-2 | ViT-Small JEPA | ViT-Small JEPA + derived features |
|---|---|---|---|
| 0 SWINGUP  (17.6%) | 0.0639 | 0.0749 | **0.0552** |
| 1 BALANCE  (79.4%, majority) | **0.0132** | 0.0265 | 0.0172 |
| 2 RESET    (3.0%, minority) | 0.1042 | 0.0845 | **0.0738** |
| all | **0.0251** | 0.0379 | 0.0269 |

The from-scratch JEPA encoder alone lowers NED on the rare RESET
minority by 0.020 but raises it on the BALANCE majority by 0.013
relative to Chronos-2. Diagnostic probes
(`outputs/fm_candidates/results/`) localise the regression entirely to
operand-2 (branch-target) prediction, concentrating at PLC
edge-detector branch sites in the controller source
(`plclib.c::turn_on_with_delay` and `turn_off_with_delay`). These
branches depend on boolean threshold crossings of sensor signals.

Adding 16 derived sensor-window features (threshold magnitudes,
`cos`/`sin`/`log` saturation terms, 5-tick lags) as an extra side
input to the decoder closes most of the state-1 gap and lowers
state-0 and state-2 further. Aggregate is then within 0.002 of
Chronos-2 while state-0 and state-2 are both better than Chronos-2.
See `outputs/fm_candidates/results/decoder_conditioning_experiments.md`
for the comparison against alternative interventions
(state-balanced training sampler, factored opcode/operand head) that
did not meet the per-state goals.

## Evaluation protocol

The canonical evaluation is the `100K` subset, 5 folds.

The `100K` subset is built from the two held-out test sessions
(`2025-03-25_13-39-06` and `2025-03-26_11-03-04`) by taking every
rare-state tick they contain and filling the rest of the budget with
a deterministic sub-sample of the majority state:

* every state-0 (SWINGUP) tick: 17,581
* every state-2 (RESET) tick: 3,007
* state-1 (BALANCE) sub-sample drawn deterministically via
  `EVAL_SUBSET_SEED=1234567`: 79,412
* total: 100,000

Per fold the generator-train split changes; the encoder is shared
across folds. Aggregation reports the median, [min, max], and the
five raw fold values. Mean and standard deviation at n=5 are
under-powered. See
[outputs/fm_candidates/collect_5fold_results.py](outputs/fm_candidates/collect_5fold_results.py).

### Determinism

* `determinism.set_deterministic(seed=42)` at every train and eval
  entry point.
* `CUBLAS_WORKSPACE_CONFIG=:4096:8` exported in every SLURM job.
* Evaluation pinned to H100 SXM5 via `--gres=gpu:H100:1`.
* Same seed, same GPU SKU, same PyTorch build yields bit-exact
  outputs. Changing GPU SKU breaks bit-identity at the kernel level.

## Setup

Tested on Python 3.10 with PyTorch 2.x on CUDA 12.1. Build a fresh
environment with the packages below; the SLURM wrappers in this repo
expect `python3` to resolve to it.

```bash
# create and enter an environment (conda or venv, your choice)
conda create -n cps python=3.10 -y && conda activate cps
# or:  python3.10 -m venv .venv && source .venv/bin/activate

# core
pip install "torch==2.4.*" --index-url https://download.pytorch.org/whl/cu121
pip install numpy pandas pyarrow openpyxl scipy scikit-learn lightgbm tqdm

# foundation-model dependencies (Chronos-2, MOMENT-1)
pip install transformers accelerate einops

# plotting / EDA
pip install matplotlib seaborn

# video conditioning (V-JEPA-2, CoTracker3), optional
pip install opencv-python peft

# vendored vjepa2 has its own requirements.txt; install if using V-JEPA-2
pip install -r vjepa2/requirements.txt
```

If the SLURM wrappers reference an env name (`slimllm`, `slimllm_bw`),
edit `outputs/fm_candidates/run_*.sh` to point at your env's `bin`
directory.

## Reproduction

```bash
cd outputs/fm_candidates

# Build per-tick parquet from the raw datalogs
sbatch run_build_session_pruned.sh

# Pretrain the from-scratch JEPA encoder (single GPU, about 1.5 h on H200)
sbatch run_bl7_pretrain.sh

# Pre-compute per-tick embeddings for all sessions
sbatch run_precompute_emb.sh

# Train the AR-modern decoder on those embeddings (5 folds)
sbatch submit_ar_modern_bl7_5fold.sh

# Evaluate on the `100K` test set (chunked, about 6 h per fold)
sbatch submit_stratified_100k.sh ar_modern_bl7
```

Other combinations (Chronos-2 + MDLM, Chronos-2 + AR, MOMENT-1 + AR,
and the two video-conditioning variants) use the corresponding
`submit_baselines_5fold.sh` and per-variant `run_*.sh` wrappers.

## Conventions

Each generator exposes `compute_loss(x0, sensor_emb, pad_mask)` for
training and `sample(sensor_emb, seq_len, *, greedy, temperature)` for
inference. `evaluate.py` wraps both signatures so the timing and
metrics path is shared across MDLM, AR, AR-modern, and cross-attn.

Metrics reported: NED (primary), CrystalBLEU, MAUVE, Vendi-ratio. NED
and CrystalBLEU are token-level; MAUVE and Vendi-ratio capture
distributional similarity.

`evaluate.py --baseline {unigram, copy_modal, copy_previous}` runs
floor predictors through the same metrics pipeline. The corpus is
about 98% self-similar (`self_bleu_reference` is about 0.989), so a
floor is needed to interpret surface metrics.

## Hardware

### Training

Single GPU per run (H100, H200, or L40S). JEPA encoder pretraining
takes about 1.5 h on H200. AR-modern decoder training takes about 30
min on H100 SXM5.

### Evaluation

Pinned to H100 SXM5 via `--gres=gpu:H100:1`. Each `100K` fold takes
about 6 h; cross-attention variants require `CHUNK_TIME=12:00:00`.

### Cluster

SLURM partitions `short`, `long`, `quick`. The `academic` partition
has a different access tier and is not used. Blackwell nodes
(`gpu-6-[01-20]`, sm_120) require the `slimllm_bw` env (PyTorch
nightly cu128); the default `slimllm` env's PyTorch cu121 build
covers only up to sm_90 and crashes on Blackwell.

## Release notes
This is the public code release for the IAAI-27 paper. Meta's V-JEPA2 (used by
one optional video-assessment baseline) is not vendored here; install it
separately. The paired sensor-and-trace dataset, with the controller source,
binaries, and program-counter layout, is linked from the paper and released
separately (it is not stored in git). The proprietary vendor instrumentation
that produced the ground-truth traces is not part of the release.
